# 0.6.5

这是 StaryMoon 维护版的文章编辑与更新版本，全部改动已用真实登录账号端到端验证。

## 新增：编辑已有知乎文章

- `Zhihu: Edit Article`，三个入口：
  - 文章阅读页顶部的“✎ 编辑文章”按钮。
  - 推荐 / 热榜 / 收藏树中文章条目的右键菜单。
  - 命令面板直接粘贴文章链接或文章 ID。
- 会把线上文章转换成 Markdown 草稿（不覆盖本地文件），首行
  `#!https://zhuanlan.zhihu.com/p/<id>` 携带文章身份，封面图放在标题之前。
- 数学公式（`formula` 图片）还原为 `$...$` / `$$...$$`，懒加载图片取真实
  `src`，未知自定义卡片原样保留。

## 改进：可靠的原文更新

- 首行是文章链接时执行 `Zhihu: Publish Current Markdown`（含定时发布）会
  更新原文章：文章 URL 和 ID 保持不变，不会误建新文章。
- 发布前重新读取原文章并校验：文章被删除给 404 提示，修改他人文章直接
  阻止。
- 发布弹窗默认高亮“保持原专栏”；删除 H1 前的封面图会显式清空封面；
  评论权限自动映射为发布接口接受的枚举。
- 严格执行“保存草稿 → 发布”顺序，草稿保存失败绝不触发发布。
- 博客文件的 YAML front matter 在发布前自动剥离。
- 定时发布任务改为可序列化操作模型，VS Code 重启后按原操作恢复；
  旧的更新任务不再退化成新建文章。

## 修复

- 收藏夹中文章条目无法加载（`Collection target fetch failed:
  type=article`）：知乎已对 `www.zhihu.com/api/v4/articles` 接口开启风控
  （403 code 10003），文章阅读页与收藏树改用 `zhuanlan.zhihu.com/api/articles`
  端点，赞同数 / 评论数 / 收藏数完整。
- 登录后重启 VS Code，写操作（如导出回答）缺少 `x-xsrftoken` 被拒：
  token 现在会在发送时从 cookie 存储中补齐。

## 测试

- 测试套件 42 项通过，覆盖文章 ID 解析、HTML → Markdown 转换、草稿结构、
  发布路由、草稿 → 发布顺序、任务恢复与 front matter 剥离。
- 真实更新验证：一篇文章更新后 URL 与 ID 不变，正文原地替换。
